# Stripe test payment and confirmation email

Import `stripe-test-checkout.postman_collection.json` into Postman. Create a **local** Postman environment with `testInboxEmail` (an inbox that accepts `+checkout-...` aliases) and `emailSenderApiKey`. Keep these values out of exported collections. Request 1 generates a unique email alias, password, and cart session, then creates a test customer with a Portuguese delivery address. Change `productId` or `quantityM2` if the default real product cannot be purchased.

Set `shoppingCartBaseUrl` and `emailSenderBaseUrl` to the running services. ShoppingCart must use the PT **test** Stripe key and have persistent orders (`APP_MODE=online` with `DATABASE_URL`) if the server may restart. The two services need the same `EMAIL_SENDER_API_KEY`; EMAIL_SENDER also needs its database and SMTP configuration. For a local webhook, run `stripe listen --forward-to localhost:8080/webhooks/stripe` in test mode, put the printed `whsec_...` value in ShoppingCart's `STRIPE_WEBHOOK_SECRET`, then restart ShoppingCart. For a deployed backend, configure the test-mode Stripe webhook endpoint to POST to `/webhooks/stripe`. Never put the webhook secret in Postman.

Run requests 1–6 in order: register, log in, confirm authentication, confirm the real product, save the cart, and create Checkout. Open the returned `checkoutUrl` in a browser, enter the Portuguese shipping and billing address, check the product, shipping, VAT and total, then complete payment with a [Stripe test card](https://docs.stripe.com/testing#cards). **Pause here; do not run the full collection in one unattended Runner pass.** Run requests 7–10 after Stripe delivers `checkout.session.completed`. They check the order is `PAID`, check EMAIL_SENDER history, delete the account created in this run, and verify that account can no longer log in. The delete request is guarded against running before payment verification. A 200 webhook response and a delivery-history entry are stronger evidence than the success redirect; check the test inbox separately for actual arrival. Do not use `stripe trigger checkout.session.completed` to verify this specific order, because that creates a different Checkout Session ID. Deleting the customer does not erase retained order and email records.

**Known application blocker:** The paid webhook records Stripe's VAT-inclusive `amount_total`, but `StartClientJourneyMapper` currently requires it to equal the order snapshot's pre-VAT `total`. For a checkout where Stripe adds VAT, the order can become `PAID` while the webhook returns 503 and the confirmation email is not started. The saved invoice also still uses a temporary zero tax amount. The collection exposes this failure; it cannot repair it. Do not treat a paid order alone as proof an invoice or email was sent.
